# 只做检索，不做答案合成

`search-gateway` 只返回归一化来源，不调用任何模型、不生成答案。原方案（grok-search-rs）让上游模型兼做搜索和回答，但模型侧搜索不可控：搜索失败时答案会被丢弃，引用是否可信也无法在服务内验证。宿主模型本身已经具备总结能力，把检索和合成拆开后，来源可审计、失败可分级、换模型不影响检索链路。代价是宿主必须自己总结，非 Agent 客户端拿不到“一次调用即答案”；这是有意接受的。

## Considered Options

- 保留模型自带搜索：受网关能力约束，magpie/DeepSeek 会静默忽略 `web_search` 工具。
- 纯总结：检索后让上游模型总结；比现状可控，但仍多一层模型，且会压缩掉宿主需要的一手信息。
- 只检索（采纳）：把来源直接交给宿主，合成留在宿主侧。

## Consequences

- 工具契约里没有 `content` 答案字段；引用由宿主生成。
- 非 Agent 客户端若要“一次调用返回答案”，需要另加可选总结模式，而不是默认行为。
